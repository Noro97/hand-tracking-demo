# 032 — Прицеливание: курсор вместо луча (фикс «не стреляет туда, куда показываю» и тряски)

**Status:** done
**Created:** 2026-08-14
**Origin:** user-reported — «aiming and shaking not works correctly… need to shoot exactly pointing to screen»
**Impact:** high (игра была фактически неуправляемой)  **Effort:** M  **Risk:** low

## Диагноз (не догадка — проверено по коду)

Зеркало оказалось **ни при чём**: задача 027 уже сделала всё правильно — игровой канвас имеет `transform: none`, координаты зеркалятся ровно один раз через `mirrorX`. Подтверждено численно.

Сломана была сама **модель прицеливания**. `aimRay` строил луч из 2D-проекции пальца (MCP→TIP) и отбрасывал прицел на 260 px вдоль него. Три следствия:

1. **Наведение НА экран — худший случай.** Когда палец направлен в камеру (единственный естественный способ целиться в экранную мишень), MCP и TIP проецируются почти в одну 2D-точку. Направление вырождается в шум, а при длине < 1e-6 `aimRay` вообще возвращал `null`. Ровно то, что описал пользователь.
2. **Никакого сглаживания.** `aimRay` читал сырые landmarks напрямую (`grep -c OneEuro lib/aiming.ts` → 0), тогда как `recognition.ts` свой pointer сглаживает. Дрожание шло в прицел без фильтра.
3. **Усиление шума рычагом.** Угловой шум на базе ~60 px, спроецированный на 260 px, умножался примерно вчетверо. Это и есть «shaking».

## Решение

**Курсор = кончик пальца.** Попадание — точка в круге под курсором. Никакой проекции, никакого рычага, работает при любой глубине пальца.

- `lib/aiming.ts` переписан: `Aim { cursor, muzzle }`, `aimFromHand`, `pointInCircle`, `mirrorX`/`mirrorAim`. Удалены ставшие мёртвыми `Ray`, `aimRay`, `rayCircleHit`, `pointAlongRay` (не оставлять мёртвый код — урок аудита 10.07).
- `muzzle` (сустав указательного) сохранён **только для трассера** — в детекции попадания не участвует.
- **Сглаживание курсора** — `OneEuroFilter` на каждую руку внутри контроллера (чистый, тестируемый). Константы отдельные от BBT-указателя: `beta` выше (0.02 против 0.01), потому что игровой курсор обязан успевать за резкими бросками руки.
- **Порядок операций важен:** сначала `mirrorAim`, потом сглаживание — фильтры должны отслеживать те координаты, которые реально рисуются, иначе они сглаживают одно, а видно другое.
- Сброс фильтров при потере позы — иначе при повторном наведении курсор «приезжает» из старой точки.
- Трассер теперь всегда заканчивается **на курсоре** (и при промахе тоже): промах читается как «я не попал по мишени», а не как «пуля улетела куда-то вбок».

## Notes
- Проба в браузере сначала показала «WRONG» — оказалось, я дважды вызвал `frame()` с одним и тем же timestamp, и `OneEuroFilter` корректно вернул прошлое значение по своему guard'у `dt <= 0`. Баг был в пробе, не в продукте; переделал на независимые контроллеры.
- Радиус мишени 42 px — теперь это буквально допуск прицеливания. Если на реальной камере покажется строго/легко — крутить `TARGET_RADIUS_PX`.
- Константы сглаживания (`CURSOR_BETA` и т.д.) — стартовые. Лагает → поднимать `beta`; дрожит → поднимать `minCutoff`.
- **Не проверено на реальной камере** (headless без камеры): субъективное ощущение точности и остаточное дрожание.
