## Честная оценка референса (зафиксировано до реализации)
Скриншот пользователя — **НЕ** live-стилизация: чистый вектор GTA-арт (капюшон Человека-паука, силуэт города), поза не отслеживает человека. Это оффлайн-сгенерированная диффузией картинка, показанная в квадре; фид просто обесцвечен. Пользователю это сказано прямо, предложены 4 варианта — выбран **AnimeGANv2** (настоящая живая AI-стилизация), не имитация референса статикой.

## Решения (зафиксированы)
- **Модель:** AnimeGANv2 Hayao ONNX ([vumichien/AnimeGANv2_Hayao](https://huggingface.co/vumichien/AnimeGANv2_Hayao), 8.2 МБ). Свободная, без API-ключа, полностью client-side — согласуется с on-device privacy-позицией проекта.
- **Сигнатура модели проверена ЭМПИРИЧЕСКИ**, не по документации: скачал файл, прогнал через `onnxruntime-node`, выяснил `generator_input:0` / `generator/G_MODEL/out_layer/Tanh:0`, layout **NHWC** `[1,H,W,3]` (NCHW отвергается), диапазон [-1,1], размеры **динамические** (принимает 108×192, не кратное 8).
- **Ключевое архитектурное попадание:** существующий буфер сцены 192×108 — уже идеальный вход для модели. Не нужно гонять 1280×720: инференс идёт на крошечной текстуре, которая и так рисуется в квадре.
- **Web Worker обязателен:** инференс 49 мс визуально бы дёргал ~30 Гц камеру-луп, если бы шёл инлайн.
- **Синхронный контракт `stylize` сохранён:** `AnimeGanStylizer` держит последний готовый кадр и отдаёт его мгновенно, отправляя новый инференс только когда воркер свободен. Камера никогда не ждёт модель; стилизованная картинка обновляется в своём темпе (кадры дропаются осознанно).
- **Чистая тензорная математика вынесена** в `lib/animeGanTensor.ts` (RGBA↔NHWC, нормализация/клэмп) — DOM-free, 5 юнит-тестов, по конвенции репозитория «логика тестируется без камеры».
- **Модель локально, не с CDN** (как MediaPipe): `public/models/` через `scripts/fetch-anime-model.mjs` (**отдельный** `npm run fetch-model`, НЕ postinstall — сетевой сбой не должен ломать `npm install`).
- **ORT wasm НЕ копируется в `public/`** — Vite сам резолвит его через модульный граф и эмитит как хешированный ассет (подтверждено в build-выводе). Первая попытка копировать в `public/ort/` + `ort.env.wasm.wasmPaths='/ort/'` была **ошибкой**: ORT начинает *импортировать* лоадер из `public/`, что Vite запрещает («should not be imported from source code»). Скрипт копирования удалён, 92.6 МБ дублирования убрано.
- **`optimizeDeps.exclude: ['onnxruntime-web']`** в `vite.config.ts` — обязательно: esbuild-пребандлинг переписывает динамическую загрузку wasm и ломает `initWasm()` в dev (`no available backend found`). Прод-сборка не затронута.
- **Graceful degradation:** нет модели → статус-строка в UI с подсказкой `npm run fetch-model`, эффект показывает сырой кадр вместо краша.
- **`useSyncExternalStore`** для статуса модели — правильный React-API для внешнего мутабельного стора (stylizer живёт вне React, им управляет canvas-луп). Решил реальную ошибку линтера `react-hooks/set-state-in-effect` по существу, а не подавлением.

## Найденный и исправленный баг (сообщил пользователь по ходу задачи)
Первая верификация была **недостаточной**: я прогнал инференс, импортировав ORT-бандл напрямую, что **обошло реальный путь приложения** (воркер + `wasmPaths`). Пользователь получил две ошибки, которых мой тест не поймал:
1. `Failed to load url /ort/ort-wasm-simd-threaded.jsep.mjs … should not be imported from source code` → убран `public/ort/` + `wasmPaths` целиком (Vite и так всё эмитит).
2. `no available backend found. ERR: [wasm] previous call to 'initWasm()' failed` → `optimizeDeps.exclude: ['onnxruntime-web']`.

**Урок:** проверять фичу через тот же модуль/путь, которым пользуется приложение, а не через параллельный «прямой» вызов — иначе верификация зелёная, а фича сломана. Заодно исправлена вводящая в заблуждение подсказка в UI: `npm run fetch-model` теперь предлагается только при ошибках загрузки модели, а не при отказе backend'а.

## Дополнение — фикс «в рамке видно весь экран» (сообщил пользователь)
**Симптом:** квад показывал уменьшенную копию ВСЕГО кадра (включая собственные руки и лицо), а не то, что находится за рамкой.

**Причина:** `drawImageInQuad` натягивал исходник целиком (0,0 → sw,sh) на квад — по сути «весь экран, сжатый в рамку», а не окно.

**Фикс:** текстура берётся только из области ЗА квадом. Новые чистые функции в `lib/quadMapping.ts` (+8 тестов):
- `sourceSize(source)` — размеры любого `CanvasImageSource` (video/image/canvas/ImageBitmap/VideoFrame) через duck-typing; null пока размер недоступен.
- `sourceRectForQuad(quad, canvasW, canvasH, srcW, srcH)` — bbox квада, клампится к канвасу, масштабируется в координаты исходника (движок рисует source растянутым на канвас, поэтому пересчёт линейный).

Контракт `SceneEffectDef.stylize` получил пятый параметр `rect: SourceRect`; общий первый шаг вынесен в `drawCropped`. Рект считается по **сглаженным** углам — область сэмплирования следует за отрисованной рамкой, а не за дрожащими сырыми landmarks.

**Ограничение (осознанное):** используется axis-aligned bbox, поэтому повёрнутый квад показывает чуть больше, чем строго закрывает. Настоящее inverse-сэмплирование дороже и визуально неотличимо на этом масштабе.

**Проверено в браузере на синтетическом исходнике** (белый верх-лево / чёрный остальной): квад над белым → highlight-полоса `245,245,245`; квад над чёрным → shadow-полоса `22,22,28`. При старом поведении оба дали бы одинаковый усреднённый результат. 79 тестов.

## Дополнение 2 — фикс горизонтального зеркалирования (сообщил пользователь)
**Симптом:** содержимое рамки отзеркалено относительно сцены за ней — «окно» показывает не то, что позади.

**Причина (найдена воспроизведением, не догадкой):** `quadFromHands` брал TL от руки с меткой `'Left'`. Но `SWAP_HANDEDNESS` делает эту метку означающей «рука, которую пользователь видит слева на ЭКРАНЕ», а из-за CSS-зеркала (`canvas { scaleX(-1) }`) эта рука лежит на БОЛЬШЕМ canvas-x. То есть TL оказывался правее TR → квад намотан задом наперёд → текстура отражена. Обрезка (Дополнение 1) сделала дефект очевидным: рамка стала окном, и рассогласование с фоном стало видно.

**Фикс:** углы упорядочиваются по фактическому canvas-x, а НЕ по метке руки. Побочно снимает [LOW] из аудита 10.07 (скрещенные руки давали самопересекающийся «бантик»).

**Воспроизведение до фикса** (синтетический исходник: левая половина белая, правая чёрная; руки в реальной зеркальной раскладке — метка `'Left'` на canvas-x 480, `'Right'` на 160):
- было: внутри квада слева `22,22,28` (чёрный), справа `245,245,245` (белый) — **инверсия**;
- стало: слева `245,245,245`, справа `22,22,28` — совпадает с фоном; та же проверка для не-зеркальной раскладки даёт тот же корректный результат.

Добавлен regression-тест `orders corners by canvas x, not by handedness label`. 80 тестов.

## Дополнение 3 — фильтры внутри рамки (запрос пользователя: «glasses for example»)
**Задача:** нарисовать лицевые фильтры (очки/шляпа/усы) на лице, которое видно ВНУТРИ двуручной рамки — рамка становится «зеркалом», показывающим тебя в очках.

**Препятствие:** на экране Hand Filters лицевого трекинга не было вообще, а просто добавить `useFaceTracking` рядом нельзя — каждый движок создаёт СВОЙ `Camera` на том же `<video>`, две камеры конфликтовали бы за кадры.

**Решение:** одна камера — две модели. `HandEngine` получил **ленивый** Face Mesh: `getSceneFaceFilters()` возвращает пустой список → Face Mesh не создаётся вовсе (нулевая цена, когда фича не используется); при первом непустом списке модель создаётся один раз и переиспользуется (init дорогой, дёргать per-frame нельзя). `camera.onFrame` шлёт кадр в оба решения.

**Координаты:** новая чистая функция `remapLandmarksToRect(landmarks, srcW, srcH, rect)` (+4 теста) переводит нормализованные координаты всего кадра в нормализованные координаты ВНУТРИ обрезки, после чего переиспользуется существующий `drawActiveFilters(..., 'face', ...)` без изменений. Значения вне 0..1 не клампятся — частично видимое лицо рисует свою видимую часть и естественно обрезается краем буфера.

**Порядок отрисовки:** фильтры рисуются ПОСЛЕ стилизации — остаются чёткой векторной графикой, а не постеризуются/превращаются в ASCII вместе с фото. (Иначе очки уехали бы в AnimeGAN на вход и «размылись» в стиль.)

**UI:** третья секция чипов «In frame» (Glasses/Hat/Mustache) на экране Hand Filters, отдельный инстанс `useActiveFilters` — независим от чипов на руки.

**Проверено в браузере:** синтетический серый исходник + синтетические landmarks глаз внутри квада → тёмных пикселей оправы: 0 без фильтра, **1520** с `glasses`. Секции UI: FILTERS / SCREEN / IN FRAME; консоль чистая. 84 теста (было 80).

**Не проверено:** совмещение на реальном лице и стоимость двух моделей на одном потоке (Hands + FaceMesh + возможно AnimeGAN). Ожидаемо просядет fps — если заметно, первый рычаг: понижать частоту FaceMesh (слать каждый N-й кадр), лицо движется медленнее рук.
